# E0820: Invalid Isolated Task Type or Worker

## Explanation

`std.task.spawn` only accepts an unqualified, same-package, non-generic
top-level function with the exact signature
`fn(TaskContext, string) -> string`. The internal `task fn` callback type is
reserved for the canonical `std.task.spawn` declaration and cannot be stored
or exposed by application code.

`Task` and `TaskContext` are runtime-owned opaque values. Application code
cannot construct them directly or access their internal handle fields.

## Error Example

```nomo
package app.main

import std.task

fn worker(input: string) -> string {
    return input
}

fn main() -> void {
    task.spawn(worker, "hello")
}
```

## Correct Code

```nomo
package app.main

import std.task

fn worker(context: TaskContext, input: string) -> string {
    return input
}

fn main() -> void {
    let spawned: Result<Task, TaskError> = task.spawn(worker, "hello")
}
```

## Fix

Declare a non-capturing top-level worker in the package that calls
`task.spawn`. Give it immutable `TaskContext` and `string` parameters and a
`string` return type. Pass the function name directly instead of a method,
closure, imported function, extern function, or local value.

Obtain `Task` values only from `task.spawn`, pass `TaskContext` only to
`task.is_cancelled`, and use the public lifecycle operations instead of
reading or constructing runtime handles.

# E0821: Task-Unsafe Worker Call Graph

## Explanation

An isolated task worker, or a Nomo function it calls transitively, uses an
operation that is not classified as task-safe. This prevents thread-confined
handles, application FFI, unsafe code, nested task creation, terminal I/O, and
other unknown effects from entering a native worker thread.

The diagnostic includes the rejected operation and the call path from the
worker.

## Error Example

```nomo
package app.main

import std.io
import std.task

fn helper(input: string) -> string {
    io.println(input)
    return input
}

fn worker(context: TaskContext, input: string) -> string {
    return helper(input)
}

fn main() -> void {
    let spawned: Result<Task, TaskError> = task.spawn(worker, "hello")
}
```

## Correct Code

```nomo
package app.main

import std.task

fn helper(input: string) -> string {
    return input
}

fn worker(context: TaskContext, input: string) -> string {
    return helper(input)
}

fn main() -> void {
    let spawned: Result<Task, TaskError> = task.spawn(worker, "hello")
}
```

## Fix

Move the rejected side effect to the parent thread, or replace it with an
explicitly task-safe operation. Workers may use pure language computation,
local managed values, the documented pure standard-library modules,
monotonic time and sleep, non-streaming `std.http` requests, and
`task.is_cancelled`.

# E0830: Invalid SQLite Operation or Opaque Handle Use

## Explanation

A `std.sqlite` operation has the wrong arity or argument types, or application
code attempted to construct, inspect, or mutate a runtime-owned
`SqliteDatabase` or `SqliteQuery` handle.

SQLite handles are opaque capabilities. Only `sqlite.open`,
`sqlite.open_memory`, and `sqlite.query` create them; the public lifecycle
functions consume copied capability values while the runtime registry decides
whether each handle is still live.

## Error Example

```nomo
package app.main

import std.sqlite

fn main() -> void {
    let database: SqliteDatabase = SqliteDatabase { handle: 1 }
}
```

## Correct Code

```nomo
package app.main

import std.sqlite

fn main() -> void {
    let opened: Result<SqliteDatabase, SqliteError> = sqlite.open_memory(0)
}
```

## Fix

Use the exact signatures declared by `std.sqlite`. Pass a string path,
`SqliteOpenMode`, and `u64` timeout to `open`; pass
`Array<SqliteValue>` bindings to `execute`, `query`, and `reset`; and obtain
database/query handles only from successful standard-library calls.

Do not construct an opaque handle or access its internal field. Close queries
with `sqlite.close_query` before closing their database with `sqlite.close`.

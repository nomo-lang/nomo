# E0870: Suspend Call From a Synchronous Function

## Explanation

A normal `fn` has no coroutine frame or async runtime context, so it cannot
call a function declared with `suspend fn`. A suspend function may call both
synchronous and suspend functions, and its call sites remain direct-style.
Compiler-recognized `task.deadline(...) { ... }` and
`task.check_cancelled()` also require a suspend caller because they read or
modify the current task's structured runtime state.

## Error Example

```nomo
suspend fn fetch() -> string {
    return "ready"
}

fn main() -> void {
    let value: string = fetch()
}
```

## Correct Code

Mark the caller as suspend so the effect is explicit in its signature:

```nomo
suspend fn fetch() -> string {
    return "ready"
}

suspend fn main() -> void {
    let value: string = fetch()
}
```

## Fix

Add `suspend` before the caller's `fn`. If synchronous code intentionally needs
a blocking operation, use a documented blocking boundary instead of hiding the
suspend effect.

## LSP Code Action

No automatic code action is provided in the P0 implementation.

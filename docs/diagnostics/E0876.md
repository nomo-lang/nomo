# E0876: Unsupported Suspension Shape

## Explanation

The current P1 runtime slice lowers `task.yield_now()` and direct calls to
actually suspending functions when they are standalone statements in
non-generic, parameterless `suspend fn` functions returning `void`. Each call
site embeds one child frame; recursive suspend graphs would need dynamically
sized frames and remain unsupported.

Immutable top-level locals may live across suspension when all transitive value
fields are frame-safe. Mutable locals, borrows, guards, resource handles or
wrappers containing them, arguments/results, `?`, explicit panic, nested
control flow, a local initializer, an argument expression, or another
expression need frame, result, or unwind rules that are not implemented yet.

This diagnostic prevents the compiler from silently generating synchronous or
incorrect C99 code for a suspension shape that the runtime cannot preserve.

## Error Example

```nomo
import std.task

suspend fn helper(value: string) -> string {
    task.yield_now()
    return value
}

suspend fn main() -> void {
    let value: string = helper("ready")
}
```

## Correct Code

For this implementation slice, keep each suspension as a standalone
direct-style call. Immutable top-level locals may cross it:

```nomo
import std.io
import std.task

suspend fn helper() -> void {
    let message: string = "ready"
    task.yield_now()
    io.println(message)
}

suspend fn main() -> void {
    helper()
}
```

## Fix

Keep the suspend call chain acyclic, parameterless, and `void`-returning; move
each suspension out of control flow, initializers, arguments, and other
expressions; and keep cross-suspension locals immutable and within the
supported value types. Wait for the later parameter/result, control-flow, and
complete unwind slices when those semantics are required. Do not replace a
required nonblocking boundary with a blocking operation merely to avoid the
diagnostic.

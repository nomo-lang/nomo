# E0876: Unsupported Suspension Shape

## Explanation

The current P1 runtime slice lowers `task.yield_now()`, `let`-bound
`task.sleep(Duration)` results, and direct calls between non-generic actually
suspending functions. Immutable frame-safe parameters evaluate once into the
child frame, and value results move into an immutable top-level `let` before
child drop. Each function call site embeds one child frame; recursive suspend
graphs would need dynamically sized frames and remain unsupported.

The first structured-concurrency slice additionally lowers a top-level
`task.scope` containing inferred immutable
`task.spawn child(args)` handles and exactly one
`task.join(handle) -> Result<T, TaskError>` or
`task.cancel(handle) -> Result<void, TaskError>` per child. Child targets must be
non-generic top-level suspend functions with immutable parameters and a
frame-safe result type.

Immutable top-level locals may live across suspension when all transitive value
fields are frame-safe. Mutable parameters/locals, borrows, guards, resource
handles or wrappers containing them, `?` outside the structured binding below,
panic nested inside another expression, nested control flow, suspending
argument expressions, nested task scopes, structured child results that are
not frame-safe, or other nested suspending expressions need transfer or unwind
rules that are not implemented yet. A direct top-level `panic(message)` or
`debug.panic(message)` statement is supported when its message does not
suspend or contain another early exit. Async `main` also remains `void` until
its result-to-process-status ABI lands.

A `task.scope` may end with `return` when the scope is the function final
statement. The compiler evaluates the return expression into an owned
temporary, cancels and drops live children, then moves the value and completes
the helper. Normal scope fallthrough uses the same cleanup. A non-final return
and all other early-control-transfer shapes remain unsupported.

Inside a top-level `task.scope`, an immutable direct
`let value: T = expression?` is supported when `expression` is non-suspending
or exactly `task.join(handle)`. Err/None is stored as an owned helper result,
children live at that statement are cancelled and dropped, and the helper
completes. The success payload may cross a later suspension when it is
frame-safe. This slice still requires the explicit `T` annotation.

Structured cancel is likewise supported only as a direct immutable top-level
binding:
`let cancelled: Result<void, TaskError> = task.cancel(handle)`. It consumes the
handle after terminal cleanup. Nested cancel expressions and discarded
structured cancel results remain unsupported in this slice.

The first deadline slice supports one non-nested
`task.deadline(Duration) { ... }` per suspend function. The block produces no
value and must fall through normally. Its top-level body may use the already
supported direct suspend and structured-child forms plus
`task.check_cancelled()`. A second or nested deadline, a nested scope, control
flow, `return`, `?`, panic, defer, or unsafe inside the deadline body reports
E0876 until the general structured-exit lowering is implemented.

P3-B additionally accepts a direct immutable top-level
`let sent: Result<void, ChannelSendError<T>> = task.send(channel, value)` or
`let received: Option<T> = task.receive(channel)`. The channel and value
expressions must not themselves suspend. Nested channel suspension in control
flow or another expression remains unsupported.

P3-C accepts a statement-level static select with 2 through 8 direct
`task.receive` or `task.sleep` arms. Arm bodies must be non-empty,
non-suspending, and fall through normally. `return`, `break`, `continue`,
panic, `?`, defer, unsafe/nested structured scopes, nested select, and
send/join selection still report E0876 until general structured-exit lowering
lands.

This diagnostic prevents the compiler from silently generating synchronous or
incorrect C99 code for a suspension shape that the runtime cannot preserve.

## Error Example

```nomo
import std.task

suspend fn helper(mut value: string) -> string {
    task.yield_now()
    return value
}

suspend fn main() -> void {
    let value: string = helper("ready")
}
```

## Correct Code

For this implementation slice, bind value-returning suspend calls and
`task.sleep` with immutable top-level `let` declarations. Immutable frame-safe
parameters, results, and locals may cross either boundary:

```nomo
import std.io
import std.num
import std.result
import std.task
import std.time

suspend fn helper(message: string) -> Result<string, NumError> {
    let waited: Result<void, TaskError> = task.sleep(time.duration_millis(10))
    task.scope {
        let parsed: i64 = num.parse_i64("42")?
        return Ok(message)
    }
}

suspend fn main() -> void {
    let message: Result<string, NumError> = helper("ready")
    io.println(result.is_ok(message))
}
```

## Fix

Keep the suspend call chain acyclic and non-generic; bind every value-returning
suspend call, `task.sleep`, `task.send`, and `task.receive` result. Move
suspensions out of control flow,
nested expressions, and argument expressions, and keep parameters/results plus
cross-suspension locals immutable and frame-safe. In `task.scope`, use only
top-level immutable spawn/join bindings and frame-safe child results for this
slice; bind structured cancel directly to an immutable typed result. Normal
fallthrough, a final `return`, and a direct immutable `?` binding
cancel unjoined children on their respective exit paths. A direct panic
recursively cancels the root task tree and drops all frames before reporting
the owned message; move a nested panic to its own statement when possible.
Keep every other scope exit shape for the later mutable or affine transfer,
cancellation propagation, control-flow, and complete unwind slices. Do not
replace a required nonblocking boundary with a blocking operation merely to
avoid the diagnostic.
For a deadline, keep the first slice to one flat fallthrough block and move
unsupported exits outside it; do not catch or simulate timeout with blocking
sleep.

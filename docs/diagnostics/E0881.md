# E0881: Binding Used After Publication Move

## Explanation

A non-Copy named binding was consumed by a compiler-known publication
boundary and is used again. Structured spawn consumes named strings, arrays,
maps, and structurally Send aggregates. `task.send` and `task.try_send` use the
same consuming rule and return an unsent owner only through their typed result.
The compiler also rejects consuming the same binding twice in one publication
statement. Numeric, Boolean, and character values are Copy and remain
available.

There is no `move` keyword in this language slice.

## Error Example

```nomo
import std.task

suspend fn consume(message: string) -> void {
    task.yield_now()
}

suspend fn launch(message: string) -> void {
    task.scope {
        let child = task.spawn consume(message)
        let reused: string = message // E0881
        let joined: Result<void, TaskError> = task.join(child)
    }
}
```

## Correct Code

Construct an independent value before publication when both tasks need a
logical copy:

```nomo
import std.string
import std.task

suspend fn consume(message: string) -> void {
    task.yield_now()
}

suspend fn launch(message: string) -> void {
    let child_message: string = message.concat("")
    task.scope {
        let child = task.spawn consume(child_message)
        let joined: Result<void, TaskError> = task.join(child)
    }
    let reused: string = message
}
```

## Fix

Stop using the binding after it is published, create an independent value
before the boundary, or change the published type to a Copy value when that
matches the data model. Do not publish one binding twice in the same statement.
For a failed channel send, recover the value from
`ChannelSendError<T>`/`ChannelTrySend<T>` instead of reusing the source binding.

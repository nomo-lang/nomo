# E0883: Structural Send Derivation Failed

## Explanation

A spawn or channel publication argument is an aggregate whose first non-Send
field is Local/!Send, or the source attempts to move only one managed field.

Compiler-known Send is structural and cannot be implemented or overridden by
user code in P3-A. The diagnostic reports the first failing type path without
printing values.

## Error Example

```nomo
import std.sqlite
import std.task

struct Work {
    input: string
    database: SqliteDatabase
}

suspend fn consume(work: Work) -> void {
    task.yield_now()
}

suspend fn launch(work: Work) -> void {
    task.scope {
        let child = task.spawn consume(work) // E0883: Work.database
        let joined: Result<void, TaskError> = task.join(child)
    }
}
```

## Correct Code

Publish a Send-only aggregate and keep owner-affine handles on their original
task:

```nomo
import std.task

struct WorkMessage {
    input: string
}

suspend fn consume(work: WorkMessage) -> void {
    task.yield_now()
}

suspend fn launch(work: WorkMessage) -> void {
    task.scope {
        let child = task.spawn consume(work)
        let joined: Result<void, TaskError> = task.join(child)
    }
}
```

## Fix

Extract copied data and publish an aggregate whose complete nested type graph
is Send. Moving only `work.input` is also rejected because P3-A transfers
ownership bits for whole bindings; construct an owned temporary or move the
entire Send-only aggregate. A `Channel<Work>` declaration fails for the same
`Work.database` path even before a send is attempted.

## LSP Code Action

No automatic code action is provided.

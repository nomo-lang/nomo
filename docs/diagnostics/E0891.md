# E0891: Blocking Operation Reached From a Suspend Function

## Explanation

Some compatibility operations block the current OS thread. A `suspend fn`
must not reach them directly or through synchronous helper functions because
doing so would occupy the async executor instead of yielding to its reactor.
E0891 currently covers:

- `time.sleep`, `time.sleep_millis`, `net.connect_blocking`, and the blocking
  `TcpStream` compatibility methods;
- `http.get_blocking`, `http.post_blocking`, `http.send_blocking`,
  `http.open_stream_blocking`, `http.read_text_blocking`,
  `http.next_sse_blocking`, plus blocking `http.listen`, `http.accept`, and
  `http.respond_string`;
- `process.spawn`, `process.status`, `process.exec`, `process.output`,
  plus `process.start_blocking`, `write_stdin_blocking`,
  `close_stdin_blocking`, `next_event_blocking`, `try_wait_blocking`,
  `terminate_blocking`, and `close_child_blocking`.

The compiler checks the complete transitive call graph, including public
functions imported from project modules. The diagnostic reports only function
and API names in the call path. Its rendered source excerpt is replaced with a
safe `operation(...)` label, so it never includes argument values or secrets.
Synchronous functions and legacy isolated native workers may continue to use
the blocking APIs.

## Error Example

```nomo
import std.time

fn pause() -> void {
    time.sleep_millis(100)
}

suspend fn main() -> void {
    pause()
}
```

This reports the path `main -> pause -> time.sleep_millis`.

## Correct Code

Use the owner-local monotonic timer and handle its result:

```nomo
import std.task
import std.time

suspend fn main() -> void {
    let waited: Result<void, TaskError> =
        task.sleep(time.duration_millis(100))
}
```

## Fix

Use a matching nonblocking suspend operation when one exists (`task.sleep`,
`net.connect`, unsuffixed `http.get`/`post`/`send`/stream pulls,
`process.start`, or `process.next_event`) and handle its result.
The process suspend ABI currently returns ready `unsupported` until its native
reactor slice lands; do not replace that boundary with a hidden blocking call.
Keep remaining compatibility calls outside async execution or move the entire
blocking operation behind the bounded blocking pool. Wrapping a blocking
operation in another helper does not avoid E0891 because the compiler follows
the transitive call graph.

## LSP Code Action

No automatic code action is provided because choosing between a timer and the
blocking pool changes cancellation, deadline, and ownership behavior.
